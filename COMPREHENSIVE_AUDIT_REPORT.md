# OpenScript Comprehensive Audit Report

**Date:** 2026-07-06
**Scope:** Full-codebase audit of media index, stickers/images/GIFs, HyperFrames, agentic UX flow, TTS/STT stack, synthetic fallbacks, and known bugs.
**Method:** 4 parallel deep-audit agents + master synthesis + targeted fixes.

---

## Executive Summary

OpenScript has 70 MCP tools, 216 passing tests, zero compiler warnings, and a working golden trajectory (`script.parse` → `script.to_video`). However, the audit found that **many features exist as tool definitions but are not wired end-to-end into the content-creation flow**. The user's observation is correct: stickers, GIFs, images, and HyperFrames motion graphics are not efficaciously used.

**Root cause:** The golden trajectory (`script.to_video`) uses FFmpeg's `render_multilayer` directly. It does NOT call HyperFrames, does NOT use the SVG puppet sticker pipeline, does NOT call `gif.search` or `media.search`, and does NOT let agents choose the render engine. The HF tools, sticker tools, and media search tools exist as isolated toolsets that an agent must invoke manually — they are not integrated into the one-call orchestrator.

## 1. Media Index Audit (Phase B)

### What works
- `music.search` returns 20 tracks with mood/energy/loopable filters
- `sfx.search` returns 261 entries with editorial_role/category filters
- `library.search` returns 500+ YouTube-scraped tracks (via `library.build`)
- `broll.fetch` searches Pexels (requires API key)
- `background.fetch` has a 4-level fallback chain (Pexels → YouTube → fallback_pool → procedural)
- `stock.search` queries Pixabay (requires API key)
- `youtube.search` + `youtube.download` support range download via yt-dlp

### What's broken / fixed in this round
| Issue | Status | Fix |

| `music.assign` / `sfx.assign` / `broll.assign` hardcoded fade_in/fade_out | ✅ FIXED | All three now expose `fade_in_ms` / `fade_out_ms` as parameters |
| `broll.suggest` hardcoded `concept:"b-roll"` for every suggestion | ✅ FIXED | Now derives concept from segment caption text (first 3 words) |

| `script.to_video` falls back to procedural backgrounds silently | ✅ FIXED | Now warns per-scene: "using SYNTHETIC procedural fallback" |
| `media.search` description promises non-existent `media.download` tool | ✅ FIXED | Description now says "download manually" |
| `gif.search` description promises non-existent `gif.download` tool | ✅ FIXED | Description now says "download manually" |

### Remaining gaps (documented as known bugs)
- 20 synthetic music MP3s are still the DEFAULT for `music.search` (not just a fallback) — agents must discover `library.search` or `stock.search` separately
- `broll.fetch` hard-fails without `PEXELS_API_KEY` (no fallback chain, unlike `background.fetch`)
- `broll.fetch` results omit `duration` (PexelsVideo struct doesn't capture it)
- `media.download` and `gif.download` tools don't exist (descriptions now say so)
- `library.search` has no mood/energy/duration/source filters (text-only)
- SFX index has placeholder loudness values (`peak_db=0.0`, `loudness_lufs=0.0` for all 261 entries)
- No video/b-roll index exists (every search hits Pexels/YouTube live)
- No unified cross-source media search (agent must know 7+ search tools)

## 2. Stickers / Images / GIFs Audit (Phase C)

### Verdict: NOT effectively wired

| Feature | Discover? | Search? | Place on timeline? | Render? | Frontend UI? |
|---------|-----------|---------|-------------------|---------|-------------|
| **SVG puppet stickers** (lip-sync) | ✅ `help.tool` finds `sticker.load_preset` | ✅ `sticker.load_preset` works | ❌ No `Sticker` track type, no `sticker.assign` | ❌ HTML generated by `sticker.render` is NEVER rendered via `hf.render` — orphaned | ❌ No sticker tab |
| **GIFs** (GIPHY) | ✅ `help.tool` finds `gif.search` | ✅ `gif.search` works | ❌ No `gif.download`, no `gif.assign` | ⚠️ `script.to_video` auto-downloads GIFs internally (agent has no control over which GIF) | ❌ No GIF tab |
| **Images** (Pexels/Openverse) | ✅ `help.tool` finds `media.search` | ✅ `media.search` works | ❌ No `media.download`, no `media.assign` | ❌ Nothing consumes image-search results | ❌ No Image tab |

### Dead code found
- `generate_sticker_composition` (sticker.rs, ~200 LoC) — produces HTML files that nothing consumes
- `sticker.load_preset` handler — callable but the loaded preset data has no consumer
- `sticker.render` handler — produces HTML that is never rendered via `hf.render`
- `StickerPreset.mouth_shapes` and `emotes` fields — deserialized but never read (8 SVG files per preset = dead weight)
- `SpeakerSpec.preset` field — deserialized but `script.to_video` ignores it (binds as `_speaker_spec`)
- `StickersSpec.lip_sync` / `blink` / `idle_bob` — deserialized but never honored
- `SpeakerLayout` enum (5 variants) — defined but never used
- `SceneSpec.sticker_visible` — deserialized but never read
- Frontend exports `stickerLoadPreset`, `stickerRender`, `mediaSearch`, `gifSearch` — never imported by any component

### The SVG puppet pipeline is severed
The amplitude→mouth-scaleY→GSAP→HTML pipeline works in unit tests, but there is **no integration path** from `sticker.render` HTML to a composited frame in the final MP4. The pipeline is severed between HTML generation and `hf.render` invocation. `script.to_video` bypasses it entirely, using GIPHY GIFs and local PNGs instead.

### Recommended fixes (ranked)
1. **Add `media.download` and `gif.download` tools** — referenced in descriptions, don't exist
2. **Add `overlay.assign` tool** (or `sticker.assign` + `gif.assign` + `media.assign`) — no way to place searched assets on timeline
3. **Wire SVG puppet pipeline end-to-end**: `sticker.render` → `hf.render` (HTML→WebM) → add WebM path to `MultiLayerRenderSpec.stickers`
4. **Honour `SpeakerSpec.preset`** in `script.to_video` — currently ignored; should branch: SVG preset → sticker.render path; "giphy" → current GIPHY path
5. **Add Sticker/GIF/Image tabs to frontend AssetBrowser**

## 3. HyperFrames Motion Graphics Audit (Phase D)

### Verdict: ISOLATED from the golden trajectory

`script.to_video` does NOT use HyperFrames. It calls `render_multilayer` (FFmpeg) directly. The HF tools exist and pass smoke tests for `hf.classify` only, but no MCP tool invokes them in the content-creation flow.

### The structural gap
```
script.to_video → render_multilayer (FFmpeg)  ← CURRENT PATH
script.to_video → ??? → composition.render (HF)  ← MISSING PATH
```

There is no `render_engine` field in `ScriptSpec::OutputSpec`. An agent cannot programmatically redirect `script.to_video` to HyperFrames.

### EDL v2 → HTML compiler is dead code
`hyperframes/src/edl_v2_to_html.ts` is a standalone CLI script — **never called by any Rust MCP tool**. No `Command::new("tsx")` invocation exists in `hf.rs` or `tools.rs`. The compiler can convert a timeline JSON to HF HTML, but nothing automates this step.

### Default `project_dir` is broken
`hf.lint` / `hf.validate` / `hf.render` default to `project_dir="hyperframes"` (hf.rs:18), but `./hyperframes/` has no `index.html` at root — only at `compositions/main-with-broll/index.html`. Invoking with default args fails.

### Motion graphics capabilities (current)
- ✅ GSAP timeline-driven opacity tweens for video layer visibility
- ✅ B-roll crossfade (hardcoded `power2.inOut` ease)
- ❌ No kinetic typography (compiler emits no text elements)
- ❌ No text animation styles (no `<div>` text layer)
- ❌ No configurable transition styles (only `power2.inOut`)
- ❌ No color scheme / font configuration
- ❌ No captions in HF (`script.build_captions` produces ASS only, not HF HTML)

### Recommended fixes (ranked)
1. **Add `render_engine: "ffmpeg" | "hyperframes"` to `OutputSpec`** — let agents choose
2. **Add `timeline.to_hyperframes` MCP tool** that wraps `edl_v2_to_html.ts`
3. **Fix default `project_dir`** — move `compositions/main-with-broll/index.html` to `hyperframes/index.html`
4. **Fix Tauri TS wrappers** — `hfLint` etc. pass `source_path` but Rust expects `project_dir`; `compositionRender` passes wrong enum values
5. **Add HF smoke tests** — only `hf.classify` is tested today
6. **Port `edl_v2_to_html.ts` to support text/caption/sticker layers** — currently emits `<video>` only

## 4. Agentic UX Meta-Audit (Phase E)

### First-contact experience (initialize response)
The `instructions` field in `handle_initialize` (server.rs:175) is **good for the from-scratch path** but **fails the "bird's-eye director" test**:
- ❌ Omits ~25 of 70 tools (no `sfx.*`, `music.search`, `library.*`, `voice.profile.*`, `voiceover.*`, `timeline.inspect/diff/preview/validate`, `reelize.timeline`)
- ❌ No decision tree for `timeline.render` vs `composition.render`
- ❌ No decision tree for `music.search` vs `library.search` vs `stock.search`
- ❌ No decision tree for `broll.fetch` vs `background.fetch` vs `youtube.download`
- ❌ NLE path is missing `srt.prepare` between `transcribe` and `edl.build`

### help.tool ranking is broken
The keyword-overlap matcher (`tools.rs:9460-9559`) has 3 of 4 broken example queries:
- "create a video from a script" → ranks `script.to_video` 3rd (behind `script.parse` and `script.to_timeline` due to alphabetical tie-breaking)
- "burn captions" → top hit is `script.build_captions` (generates ASS, doesn't burn), not `timeline.render` (which burns)
- "add voiceover to a timeline" → top hits are `timeline.add_segment` / `timeline.add_track_event`, not `voiceover.generate`

### Recommended fixes (ranked)
1. **Add `project.plan` meta-tool** — returns step-by-step tool-call plan for a natural-language goal
2. **Add stemming/synonyms to `help.tool`** — "burn"→"burned", "footage"→"broll", "VO"→"voiceover"
3. **Replace alphabetical tie-breaking with tool-weight table** — golden-path tools weighted 1.0
4. **Expand `initialize` instructions** — name all 26 families, add decision trees, add `library.*`/`sfx.*`/`voice.*`
5. **Add `voices.list` tool** — returns 54 Kokoro voice IDs (agent currently has to read JSON file)
6. **Add `quality:"draft"` parameter to `script.to_video`** — cheap preview before full render

## 5. TTS/STT Stack Audit (Phase G)

### Current stack
| Component | Technology | Status | Latest alternative? |
|-----------|-----------|--------|-------------------|
| **TTS (default)** | Kokoro TTS (ONNX, 24kHz, 54 voices) via Python sidecar | ✅ Working | Kokoro is current (released 2025). No upgrade needed. |
| **TTS (voicebox)** | faster-qwen3-tts via HTTP sidecar at :17493 | ⚠️ Optional | Qwen3-TTS is current. Sidecar architecture is legacy (fresh-process-per-call). |
| **STT (transcription)** | Apex (whisper_timestamped) via conda env | ✅ Working | whisper_timestamped is maintained but slow. Alternatives: whisper-rs (Rust native), Parakeet TDT (ONNX, faster). |
| **Force alignment** | Whisper via `whisper_align.py` Python sidecar | ⚠️ Working but slow | Fresh-process-per-call (20× cold-start penalty on 20-scene scripts). Should be long-lived sidecar or Rust port. |

### Legacy artifacts
- **Parakeet TDT** was researched and installed in a prior round but the `parakeet_align.py` file was deleted (confirmed dead). No Parakeet code remains.
- **`TranscriptionEngine` enum** has a single variant `Apex` with a "DO NOT add variants" comment — pure YAGNI but harmless.
- **`TranscribeError::ApexUnhealthy` and `OutputValidationFailed`** variants were deleted in a prior round (confirmed dead).

### Performance issue
Both Kokoro and Whisper sidecars spawn a **fresh Python process per call**:
- `kokoro.rs:123` — new `python3` per TTS chunk
- `tools.rs:5308` — new `python3` per Whisper alignment
- `transcriber.rs:352` — new conda python per transcribe call

For a 20-scene script, this means 20× ONNX model loads (~200ms each) + 20× Whisper model loads (~hundreds of ms each). A long-lived sidecar (stdin/stdout JSON protocol) or native Rust port would eliminate this.

### Recommended upgrades
1. **Long-lived Kokoro sidecar** — keep the Python process alive, communicate via stdin/stdout JSON. Eliminates 20× cold-start.
2. **Long-lived Whisper sidecar** — same pattern for `whisper_align.py`.
3. **Consider `whisper-rs`** for the alignment path — native Rust, model stays loaded, no Python dependency.
4. **Keep Apex/whisper_timestamped** for transcription — it's the only option for word-level Hinglish timestamps.
