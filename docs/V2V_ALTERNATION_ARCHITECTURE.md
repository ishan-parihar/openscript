# V2V Alternation Architecture — `[broll → video → broll]`

> **Status:** Architecture proposal (investigation complete)
> **Scope:** Video-to-video presentation mode — the full A2V pipeline (voices,
> captions, music, stickers) stays identical, but the **visual layer** alternates
> between stock b-roll and the **original video footage**, segregated by the
> transcript segmentation.
>
> Companion docs: `docs/SEGMENTATION_ARCHITECTURE.md`, `AGENTS.md §2` (golden
> trajectories), `AGENT_GUIDE.md` (tool taxonomy).

---

## 1. Investigation findings — what already exists

### 1.1 The compositing layer ALREADY renders `[broll → video → broll]`

`render_from_timeline` (`crates/openscript-ffmpeg/src/render.rs`) is the V2V
renderer today, unchanged:

1. The **original video is the base input**: `-i <source_video>` → `[0:v]`.
2. Each timeline segment trims the base: `[0:v]trim=start=s:end=e,setpts=PTS-STARTPTS`.
3. B-roll events are **full-frame cutaway overlays** composited on top of the
   base with `overlay=0:0:enable='between(t,start,end)'`
   (`crates/openscript-ffmpeg/src/filter_graph.rs` ~line 902-931, built in
   `build_post_trim`).
4. **When no b-roll event covers a window, the original video shows through.**

So the render already does exactly what the user asked for — it just needs a
timeline where **every other segment has a b-roll event and the alternating
segments have none**. The audio path (`[0:a]` trimmed per segment + voiceover +
music + SFX + loudnorm) is untouched.

### 1.2 The A2V pipeline (Trajectory B) is the chassis

The existing audio-to-video flow is:

```
transcribe → segment.analyze → srt.to_timeline → broll.auto (keywords →
validate → fetch → place → repair) → sticker.auto → captions → timeline.render
```

`broll.auto` (`crates/openscript-mcp/src/tools/tools_broll.rs:1425`) is the
one-call A2V orchestrator. It covers **every** segment and repairs until
"zero gaps remain". This is the file the alternation mode plugs into.

### 1.3 Validation already tolerates uncovered segments

`timeline.validate` (`tools_core.rs:984`) flags only:
- clips **shorter** than their window (`BROLL_GAP` via `probe_broll_gaps`),
- **repeated** clips (`BROLL_REPEAT`).

It does **NOT** flag a segment with no b-roll at all. The production-quality
scorer's `score_broll_motion` (`crates/openscript-core/src/production_quality.rs:808`)
only penalizes coverage gaps + static runs — `has_broll=false` with zero gaps
passes at full score. **Intentional bare segments (showing the original video)
will not trip any validator or scorer.**

### 1.4 Aspect mismatch is already handled

The base `[0:v]` is scaled + center-cropped to the target aspect:
`scale=-2:{h},crop={w}:{h}:(in_w-{w})/2:(in_h-{h})/2` (filter_graph.rs:888-894).
A 16:9 talking-head source becomes a 9:16 base automatically.

## 2. The gap — the planning layer

Everything needed to *render* V2V exists. What is missing is the **planning
layer**: nothing decides WHICH segments show the original video vs b-roll,
and no tool can place b-roll on a subset of segments.

| Capability | Today | Needed for V2V |
|---|---|---|
| Render base = original video | ✅ `timeline.render` source_video | ✅ none |
| Full-frame cutaway overlays | ✅ b-roll events | ✅ none |
| Place b-roll on ALL segments | ✅ `broll.auto` / `broll.fetch` | ✅ |
| Place b-roll on a SUBSET (alternate) | ❌ fetch maps concepts 1:1 to every segment | 🔨 **NEW** |
| Record which segments are "source" vs "broll" | ❌ no intent field | 🔨 **NEW** |
| Validate the alternation pattern | ❌ | 🔨 **NEW** |
| Re-voice mode (clone narration over original footage) | ⚠️ voiceover track exists but source audio not ducked | 🔨 **NEW** (optional) |

## 3. Architecture — the V2V upgrade

### 3.1 Schema: presentation directive (backward-compatible)

Extend `Directives` in `crates/openscript-core/src/timeline/schema.rs` with a
serde-defaulted `presentation` block. Old timelines (no field) behave exactly
as today:

```rust
#[derive(Serialize, Deserialize, Clone, Debug, Default)]
pub struct PresentationDirective {
    /// "cover" (default, current behaviour — broll everywhere) or "alternate"
    /// (visual layer alternates broll ↔ source video per segment).
    #[serde(default)]
    pub mode: String, // "cover" | "alternate"

    /// Which segments are b-roll (covered) vs source (original video shown).
    /// Generated by the planner when mode="alternate".
    #[serde(default)]
    pub visual_roles: HashMap<String, String>, // segment_id → "broll" | "source"

    /// Alternation cadence. "every_other" = [broll → source → broll → source].
    #[serde(default)]
    pub pattern: String, // "every_other" (default), "broll_lead", "source_lead", "every_n"

    /// Number of consecutive broll segments when pattern="every_n".
    #[serde(default)]
    pub every_n: u32,

    /// What to do with the ORIGINAL video's audio in re-voice mode:
    /// "keep" (default for V2V keep-audio) or "duck" (lower under cloned VO).
    #[serde(default)]
    pub source_audio: String, // "keep" | "duck"
}
```

Add `#[serde(default)] pub presentation: PresentationDirective` to
`Directives`. `Default` covers the legacy case (mode="cover").

### 3.2 Planner: pure function in `openscript-core`

New `crates/openscript-core/src/presentation.rs`:

```rust
/// Assign every segment a visual role per the alternation pattern.
pub fn plan_alternation(
    segments: &[Segment],
    pattern: &str,        // "every_other" | "broll_lead" | "source_lead" | "every_n"
    every_n: u32,         // used when pattern="every_n"
    broll_ratio: f64,     // 0.0-1.0 share of segments that get b-roll
) -> HashMap<String, String>  // segment_id → "broll" | "source"
```

Rules (default `every_other`, `broll_lead`):
- Segment 0 → `broll`, segment 1 → `source`, segment 2 → `broll`, …
- `source_lead` swaps the phase (starts with original footage).
- `every_n` with `every_n=2` = same as every_other; `every_n=3` = two source
  segments per broll; a `broll_ratio` of 0.0 forces all-source (pure
  captioned original), 1.0 forces all-broll (today's behaviour).
- Non-redundancy guard: adjacent segments never BOTH get b-roll from the same
  concept pool (the planner marks roles; the fetcher still cycles distinct
  clips — the existing `fresh_candidates` logic handles it).

Unit tests in `presentation.rs` cover pattern phases, ratio rounding, and
degenerate inputs (0 segments, 1 segment, ratio 0/1).

### 3.3 Tool: `broll.auto` alternation mode (minimal surface)

Extend `handle_broll_auto` args:

```jsonc
{
  "alternation": {
    "enabled": true,
    "pattern": "every_other",     // optional, default every_other
    "broll_ratio": 0.5,           // optional
    "source_audio": "keep"        // optional: "keep" | "duck"
  }
}
```

When `enabled`:
1. **Plan** — call `plan_alternation` on the segments; write
   `timeline.directives.presentation` (mode=alternate, visual_roles, pattern).
2. **Filter** — only the segments with role `broll` enter the draft →
   validate → fetch stages. The keyword pipeline (`draft_scene_keywords`,
   `broll.validate_keywords`) runs ONLY on broll-designated segments (saves
   LLM calls + Pexels downloads).
3. **Fetch/place** — `broll.fetch` currently maps concepts 1:1 to all segments
   (`tools_broll.rs` fetch auto-place loop). Add a `role` filter: skip
   segments whose `visual_roles[id] == "source"`. Source segments get NO
   b-roll event → the renderer shows original footage there.
4. **Repair loop** — `probe_broll_gaps` only checks *placed* events, so bare
   source segments never enter the repair loop. No change needed beyond
   confirming the loop skips source segments (it already will — no event = no
   gap).
5. **Stickers/captions/music/SFX** — unchanged; they run across ALL segments
   (the A2V pipeline "remains").

Add a new one-call orchestrator `video.to_video` (thin wrapper mirroring
`broll.auto`'s Stage A, but the input is a **video** — `transcribe → segment.analyze →
srt.to_timeline(source_video=the ORIGINAL video) → alternation broll.auto →
sticker.auto → captions → timeline.render`). The base layer of the render is
the original video because `srt.to_timeline` sets `timeline.source` to it and
`timeline.render` defaults to `timeline.source`.

### 3.4 Tool: `timeline.presentation` (manual mode)

Small query/mutation tool so agents (or the Tauri UI) can inspect or edit the
visual roles explicitly:

```
timeline.presentation { timeline_path }                → current mode + roles
timeline.presentation { timeline_path, mode, pattern,
                        broll_ratio, every_n }          → re-plan + persist
```

### 3.5 Validation: alternation-aware checks

`handle_timeline_validate` gains (only when `presentation.mode == "alternate"`):

1. **Intent**: every segment must have a `visual_roles` entry (`broll`|`source`).
   Missing → error with a `timeline.presentation` re-plan directive.
2. **Coverage**: broll-role segments must have a b-roll event whose clip covers
   the window (existing `probe_broll_gaps`); source-role segments must have
   **no** b-roll event (an event there is a planning error — flag
   `BROLL_ON_SOURCE`).
3. **Breadth**: the alternation must not leave >70% of segments as source
   unless `broll_ratio` was explicitly set (catches accidental all-source).

### 3.6 Re-voice mode (optional phase 2)

For "regenerate narration with a cloned voice over original footage":
- `voiceover` track already exists and mixes above `[0:a]`.
- Add `directives.presentation.source_audio == "duck"` → the filter graph
  applies `volume=` ducking to the trimmed `[0:a]` under voiceover windows
  (a tiny addition to `build_post_trim` — the sidechain ducking machinery for
  music already exists; the same pattern applies to source audio).
- This is OPTIONAL for the first implementation (keep-audio mode is the
  default and needs zero render changes).

## 5. Renderer changes

**Zero** for keep-audio mode — `render_from_timeline` already composites
`[broll → video → broll]`. Optional ducking for re-voice mode is a ~20-line
filter-graph addition.

## 6. Testing plan

1. **Unit** — `presentation::plan_alternation` patterns/phases/ratios.
2. **Integration** — `broll.auto` with `alternation.enabled=true` on a 6-seg
   fixture: assert timeline has exactly 3 b-roll events on the broll-role
   segments, `directives.presentation.mode == "alternate"`, and
   `timeline.validate` passes.
3. **Render E2E** — `video.to_video` on a short talking-head clip: output has
   h264+aac, correct duration, and the contact sheet shows alternating
   original-footage / b-roll frames at scene boundaries.
4. **Regression** — full workspace test suite (520 baseline) + `broll.auto`
   WITHOUT alternation produces identical output to today.
